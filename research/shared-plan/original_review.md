# THE ROOT 원본 기획·데이터 검토

검토일: 2026-09-26. 대상: docs의 MD 4개, JSON 1개, Excel 1개(17개 시트). 원본 파일은 변경하지 않았다.

## 결론

핵심은 지식 퀴즈 자체보다 **확신이 있는 만큼 분류를 깊게 진행하고, 관찰 비용과 오답 위험 사이에서 확정 시점을 고르는 게임**이다. 분류로 질서를 복원하다가 Overflow로 질서가 무너지고, 역분류로 새로운 행성을 만든다는 서사가 시스템과 연결돼 있다. 이 연결이 가장 큰 개성이다.

3개체 프로토타입을 시작할 수 있는 구체성은 충분하다. 다만 “현재 JSON만 읽으면 전체 Vertical Slice를 구현할 수 있다”는 수준은 아니다. 데이터 내보내기 누락과 점수 확정 규칙, 첫 상점 경제를 먼저 정리해야 한다.

## 이전 예비 분석의 정정

공개 본문만 읽었을 때 미확정으로 적은 다음 항목은 원본에서 해결됐다.

- OBSERVE: 개체당 1회, 최종 카드 점수 -30%.
- SKIP: 점수 0, Streak 초기화, 시간 -5초, Chaos +2.
- HOLD: 5칸 중 1칸 점유, 수동·Cycle 갱신 모두 유지.
- Refresh: 최대 4회, 50/100/200/400, 이후 비활성화.
- 강화 단계 확률: 장비 상품으로 결정된 뒤 적용.
- Hard Mode 티저: 복수 선택 가능. 전체 행성 시뮬레이션은 범위 밖.

이전 analysis.md는 공개 본문만 근거로 한 과거 예비 분석이며, 현재 판단은 이 문서를 우선한다.

## 데이터 검증 결과

읽기 전용 스크립트로 3,314개 비교·구조 검사를 수행했다. 이 숫자는 게임 실행 테스트 수가 아니다.

| 대상 | 결과 |
|---|---|
| 개체 | 30개, 경로 길이·Max Depth·완주 보너스 일치 |
| 질문 단계 | 173개, 정답 경로·부모·최종 단계·Excel 대응값 일치 |
| 카테고리 | Excel 107개. 질문의 참조 누락 및 다른 부모의 Distractor 없음 |
| Cycle | 각 20개. 순서·start_depth가 Excel/JSON에서 일치 |
| Hard Mode | 속성 관계 150개, 값 일치 |
| 장비·재료·강화 | 비교한 효과·기본가·숙련도·재료 필드·단계별 비용 일치 |
| 상점 확률 | 일반·첫 상점 강화 확률 및 슬롯별 타입 확률 모두 100% |
| 가격 | JSON 배수 단순 계산과 Excel 가격이 3곳 다름 |

전체 17개 시트의 모든 셀을 JSON과 일대일 비교한 것은 아니다. 구조상 대응하지 않는 설명·정책 표도 있다. 학술 출처 30개를 재검증한 결과가 아니라 내부 정합성 검사다. SQL은 현재 docs에 없다. 워크북은 수식 0개인 정적 데이터표이므로 값을 수정해도 관련 가격·누적 비용이 자동 갱신되지 않는다.

## 구현 전에 해결할 항목

### 1. [높음] JSON 단독으로는 카테고리 UI와 기본 규칙을 구성할 수 없다

JSON 최상위에 categories와 balance가 없다. 카테고리 ID는 있으나 한국어·영어 표시명, 부모·설명은 Excel Categories_Canon에만 있다. 300초, OBSERVE 기본 횟수·패널티, SKIP·오답·Fast 기본 규칙도 통합 설정으로 내보내지 않았다. steps의 observe_allowed는 Excel에 60개 false / 113개 true로 존재하지만 JSON에는 없다.

권장: categories, balance, observe_allowed를 export하고 필수 필드 검사를 추가한다. 개발자가 누락값을 코드에 임의로 채우면 문서의 “하드코딩 금지” 원칙과 충돌한다. Canon 상태, 속성 weight, 데이터·세이브 버전도 사용 목적에 맞게 명시한다.

### 2. [높음] OBSERVE를 사용한 LOCK·오답의 점수 확정 규칙이 불완전하다

기획은 OBSERVE가 최종 카드 점수에 적용된다고 하지만 개발 문서의 Complete 경로에만 적용 순서가 명시돼 있다. LOCK은 현재 점수를 bank, 오답은 50% 손실로 서술된다. 이대로 각각 구현하면 관찰 후 LOCK/오답에서 패널티가 빠질 수 있다.

권장: Complete/Lock/Wrong/Skip을 하나의 카드 정산 함수로 모으고, 경로별 적용 항목을 표로 고정한다. 예를 들어 누적 100점에서 OBSERVE 후 LOCK은 70점, OBSERVE 후 오답은 35점이라는 기준을 확정한다. 이 예시는 Streak·장비가 없는 경우의 제안이다. start_depth 이전 점수 지급 여부, LOCK 가능 최소 성공 횟수, 시간 만료 중 카드 처리, 반올림 시점도 함께 정한다.

### 3. [높음] 강화품 진열 보장이 구매·직접 강화 체험을 보장하지 않는다

일반 Cycle 보상은 350~500, 고성과 상단 650이다. +1은 420~480, +2는 Excel 기준 640~740이다. 첫 보장 슬롯은 30% 확률로 +2다. 초기 재화가 0이고 첫 보상이 350이면 보장 강화품은 하나도 살 수 없다. +2 Lens/Hourglass 740은 고성과 보상 650도 초과한다.

또 +0 구매 후 +1 직접 강화는 화폐만 400~440과 해당 재료 1개가 필요하다. 첫 보상 350에서는 초기 장비·재화가 없으면 불가능하다. 문서의 “VS에서 최소 1회 강화 체험”을 확실히 달성하려면 시작 장비, 보상 하한 보정, 전용 재료 지급, 튜토리얼 강화권 중 하나를 설계해야 한다. 초기 재화·지급품이 명시되지 않았으므로 불가능하다고 단정하는 대신 조건부 문제로 본다.

### 4. [중간] +0 장비 5종 모두 즉시 효용이 없다

Lens 30% 패널티, Hourglass +0초, Bookmark 5초/Chaos 2, Stabilizer Chaos 5, Field Notes +0%로 전부 기본 행동과 같다. 280~320을 내고 장착해도 즉시 변화가 없다. 강화 재료로서 의도된 설계일 수 있으나 구매 UI는 이를 설명해야 한다.

선택지: +0에도 작은 효과를 주거나, 미강화 장비임을 명시하고 구매 직후 강화 경험을 보장한다. Mastery의 “효과가 실제 발동했을 때”가 +0에서도 성립하는지도 정해야 한다.

### 5. [중간] 강화품 가격 배수와 프리미엄 목표가 맞지 않는다

공개 대화는 직접 강화 총비용보다 15~30% 비싸게 산다는 목표였지만, 현재 데이터는 기본가 × 고정 배수다. Lens +1은 480이다. 직접 강화는 320+120=440이므로 화폐만 비교하면 +9.1%, 재료 상점가 50까지 포함하면 490보다 오히려 싸다. Lens +4는 1,600이고 직접 강화는 기본가 320+수수료 1,000+재료 11×50=1,870이다.

가격 기준을 먼저 결정하고 가격표를 다시 계산해야 한다. 파밍 재료의 가치를 0으로 볼지, 상점가로 볼지에 따라 결과가 바뀐다.

추가로 +2 Lens/Hourglass는 320×2.3=736이지만 Excel은 740, Bookmark는 280×2.3=644지만 Excel은 640이다. 10단위 반올림으로 설명되지만 해당 규칙이 JSON에 없다. 가격 오류로 단정하기보다 가격 계산 계약의 누락으로 처리한다.

### 6. [높음] Hard Mode 티저를 현재 속성 데이터에서 바로 생성할 수 없다

티저는 Warm-blooded를 Dolphin/Shark/Penguin/Whale에 대응시키지만, JSON에는 warm_blooded 속성이 없고 whale 개체도 없다. Dolphin·Penguin에 mammal/bird 같은 관계가 있다고 해서 런타임이 자동으로 이 정답을 추론할 규칙은 제공되지 않았다.

권장: 티저용 question_id, 후보 entity_id, 정답 집합, Similarity 계산을 데이터에 명시하거나 실제 보유 속성을 사용하는 문제로 바꾼다. 과학적 정의의 적합성은 별도 출처 검토가 필요하다.

### 7. [중간] 5분 타이머와 실제 카드량의 관계를 검증해야 한다

start_depth 적용 후 모든 카드를 끝까지 맞힐 때 Cycle 1은 92회, Cycle 2는 60회 선택한다. 300초를 다 쓰면 선택당 약 3.26초/5초이며 카드 이동과 힌트 읽기도 포함된다. 반면 빠른 보너스는 카드 전체를 3초/5초 내 완주하는 조건이다. 카드당 5초라면 20장은 순수 판단 약 100초다.

따라서 각 Cycle은 “5분 고정”보다 “최대 5분”으로 체감될 수 있다. Cycle 2는 복습에 더해 선택 횟수 자체도 감소하므로 반응 시간 개선을 전부 학습 효과로 해석하면 안 된다. 실제 세션 길이를 측정하고 입력·애니메이션·힌트 시간의 타이머 포함 여부를 정한다.

### 8. [중간] Streak·ORDER·보상 공식이 아직 없다

기능 이름, 보상 범위, 일부 연출 threshold는 있지만 Streak 배율표, 정답당 ORDER, 보상 산식은 고정되지 않았다. Cycle 2 후 ORDER 100%는 연출 target으로 맞춘다고 명시돼 있다. 이는 오류가 아니라 데모 연출 선택이지만, 거의 실패한 플레이도 세계를 복원하는지 결정해야 한다. 성과 수치와 엔딩 표시값을 분리하는 방법이 있다.

### 9. [중간] 힌트 작성 원칙과 실제 문장에 차이가 있다

데이터셋 문서는 정답 카테고리 이름을 직접 말하지 않는다고 한다. 실제 힌트에는 “두족류다”, “균류이며”, “동물이다”, “이온성 화합물”, “자연위성” 같은 분류명이 있다. 해당 Depth에서는 정답 공개가 될 수 있다. OBSERVE를 정답 구매 수단으로 허용할지, 판별 속성만 주는 수단으로 유지할지 통일해야 한다. 한 힌트가 모든 Depth에 유용한지도 별도 검토가 필요하다.

### 10. [중간] 장비 효과와 재료량을 기계가 읽기 쉽게 정리해야 한다

Bookmark effect_value는 `5s / Chaos +2` 같은 문자열이고 다른 효과는 숫자다. skip_time_penalty_sec와 skip_chaos_penalty로 분리해야 표시문구 변경이 계산을 깨뜨리지 않는다. observe_penalty_pct=30을 의사코드의 `1-penalty`에 바로 넣지 않도록 % 단위 변환도 명시한다.

Materials의 일반 재료별 cycle_drop_min/max는 각 3~5지만 Economy는 일반 재료 전체 3~5다. 각 재료별 지급으로 해석하면 총 12~20이 된다. 총량 추첨 후 종류 배분이라는 계약을 명시할 필요가 있다.

### 11. [중간] 상점·세이브의 경계 조건을 더 정해야 한다

첫 상점 보장이 수동 갱신마다 적용되는지, HOLD된 강화품이 보장을 충족하는지, 보유 장비의 중복 구매를 막는지 아직 명확하지 않다. 기술 문서 전체 흐름에는 상점이 Cycle 1 뒤 한 번뿐이므로 Cycle 간 HOLD 이월은 데모 플레이만으로 검증할 수 없다.

Save 목록에 전체 상점 재고·refresh_count·난수 상태·남은 시간·현재 카드 인덱스의 계약이 충분하지 않다. 상점 재진입/불러오기로 비용 없이 새 재고를 받거나 갱신 횟수를 초기화하지 않도록 스냅샷과 복구 시점을 정한다.

## 권장 개발 순서

1. 데이터 계약 정리: 카테고리·기본 규칙·관찰 허용·가격 반올림·Bookmark 숫자 필드·티저 데이터.
2. 점수 정산 계약: Complete/Lock/Wrong/Skip/Timeout, 시작 Depth, 시간 측정·반올림.
3. 고양이 → 물 → 오리너구리 빌드: 입력, 관찰, 확정, 결과, 로그까지 구현.
4. 첫 구매와 직접 강화가 가능한 시작 재화·재료 조건을 정한 뒤 Cycle 1 → Shop → Cycle 2 연결.
5. 학습과 암기의 비중, LOCK 사용, OBSERVE 효용, 실제 소요 시간을 플레이테스트.
6. Overflow와 데이터로 정의된 Hard Mode 티저 연결.

확장 기획을 더 붙이기보다 현재 데이터 계약을 닫고 3개체 플레이를 만드는 것이 다음 단계다. 원본 정답이나 밸런스는 이번 분석에서 임의로 수정하지 않았다.
